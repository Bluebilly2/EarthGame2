# Contract M1.4 — Responsive world loading

> **Since:** the earlier owner decisions this mentions were made on 2026-09-10 (CANON rulings 19 to 22).

Opened 2026-09-10 on the owner's "continue work". Owner: Codex. This is a bounded first
part of M1.4, paying the frozen-new-world debt before adding more terrain work.
The remaining M1.4 work is layer streaming/residency, lake beds and rendering, ground
appearance, atmosphere and the streaming budget. Earlier owner decisions remain pending.

## Promises

1. New world and Continue show a loading screen before reading rasters or computing
   layers. Preparation runs on a worker; Unity objects, transports, logging and UI
   updates remain on the main thread. A second launch cannot overlap the first.
2. The screen reports actual computation stages and completed layer writes, with
   elapsed time and an animated activity indicator. It invents no percentage or ETA.
   It stays until the client has collidable terrain and its initial snapshot.
3. The worker receives resolved paths and immutable launch inputs. New worlds retain
   their deterministic layers, wake and save layout. Continue prefers its own terrain
   and reads the old bake only for a save without world layers. Corrupt or missing
   required terrain is an error, not permission to replace a world with empty ground.
4. A preparation failure shows the reason and offers return to the menu. Quitting or
   destroying Bootstrap requests cancellation between stages; it never blocks the
   main thread waiting for a worker. No server starts after cancellation. An interrupted
   creation without world.json is not offered as a saved world.
5. Tests cover creation versus continuation, progress without changed layer bytes,
   missing/corrupt terrain and cancellation. A muted, windowless built-player run
   records loading and playable frames at 1440p and 1080p; its loading evidence counts
   main-thread updates while preparation is pending and verifies progression into play.
   Failure is also exercised from the built player, including the Back-to-menu action.

## After the contract closed — 2026-09-10, Opus 5

Codex moved the game onto `WorldPreparation` and left the dedicated host on its own reader, so promise 3 held in
the game and not at the console. The host has been brought onto the same path, and what made two paths possible
has been removed:

- `EarthGame.ServerHost` calls `WorldPreparation.Load` and logs the stages the loading panel shows. A world it
  cannot open is a refusal naming the reason and exit 2, never a world standing on the region's bake.
- `WorldCreation.TryLoadTerrain` is deleted. It returned null both for a folder with no heights layer and for one
  whose heights would not parse, and each of its two callers answered null by reaching for the bake: a corrupt
  layer was met by silently standing the world on other ground, and its digest changed with it.
- `SourceRulesTests.OnlyWorldPreparationOpensASavedWorld` fails when any production file outside
  `WorldPreparation.cs` calls `WorldSave.Restore`. Proved by sabotage before it was trusted: a file added to the
  host reddened it with the offending line named, and removing that file greened it again (STANDARDS 7).
- A world opened as a region other than the one it was saved in is refused. The caller passes the region it was
  launched with, so without this two regions of one extent would swap under a save without a word: the same local
  metres, another coast.
- `RegionRaster.Load` names the file in every refusal. This message is the whole of what a player is told on the
  failure screen and an operator in the host's log, and "missing key 'width'" does not say which of a world's
  twenty-one layers to open.
