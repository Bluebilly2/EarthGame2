# Contract M1.Ba — A socket for this machine alone

**Status:** closed 2026-09-14, the exit record at the end; opened the same day, on William's "this keeps popping up",
a Windows Security Alert for `earthgame2.exe` in `Build/Player-M17c`. Owner: Claude (Fable 5.1). A follow-up to
M1.B (two players), whose transport this is.

## What was found (2026-09-14)

- **The box is raised by the test runs, not by his play.** A SOLO game (the menu's, and every scenario run as
  `-eg-mode solo`) is the server and the client in one process over the in-memory transport, and opens no socket.
  The corpus and the streaming run start the dedicated host and join it from the built game over UDP at 127.0.0.1;
  the test suite's own UDP tests do the same inside `testhost.exe`. Both ends of LiteNetLib's manager were started
  on every address (`0.0.0.0` and `::`), the client's included, and Windows' firewall asks about a program the
  moment it binds a socket on every address — once for each program path, with a box on the owner's main screen.
- **He had answered it for eight builds.** The firewall's own rule list (`netsh advfirewall firewall show rule
  name=all dir=in verbose`, read-only) holds an Allow for `earthgame2.exe` in `Build/player`, `player-m1b`,
  `player-streaming`, `player-corpus`, `player-m15d`, `player-m16b`, `player-m17a` and `player-m17c`, for
  `testhost.exe` in two checkouts, and for `dotnet.exe` (the host): every one a fresh build folder the harness ran
  as a joining client, every one a box he pressed. His network is on the Public profile with notifications on,
  which is Windows' default.

## What this slice promises

1. **An end for this machine binds the loopback address alone** (127.0.0.1 and ::1), so nothing off the machine can
   reach it and the firewall has nothing to ask: a server told `UdpOptions.LocalOnly` (the host's `+server.local
   1`, the game's `-eg-local`), and a client joining a loopback address by itself, whatever it was told.
2. **A socket meant for friends binds every address** as before: a game hosted for others and a dedicated server
   not told local. Those ask the firewall once, when someone means to be reached.
3. **Every tool that starts the host on this machine says so** (`+server.local 1`): the corpus, the streaming run,
   world creation and population, the vantages and wade runs, and the two verifiers that run the host.
4. **The test suite asks nothing** on a fresh checkout: its servers are told local and its clients join loopback.

## Non-goals

His firewall's settings and rules, which are his (an agent modifies no security setting); the rules already
written, which are harmless; a LAN game's discovery, which does not exist.

## How it is proved

`dotnet test`, each new test's reason broken once: the witness is the system's own table of bound UDP sockets
(`IPGlobalProperties.GetActiveUdpListeners`, what netstat prints), not anything the transport says of itself, and
each rule has its contrast. The Unity-layer compile. Then the box itself: a fresh build folder run as the harness
runs it, with William at the keyboard to say whether a box appeared, and the firewall's rule list read again for
a new rule (a box answered leaves one).

## Exit record (2026-09-14)

**What exists.** `UdpOptions.LocalOnly`; `UdpTransportBase.Start(localOnly, port)`, which binds the loopback
addresses or every address, and `BoundLocalOnly` and `LocalPort` to say what it did; `UdpTransportBase.IsLoopback`,
the addresses that name this machine (127.0.0.0/8, ::1, "localhost"); `UdpServerTransport.Listen` binds as told and
`UdpClientTransport.Connect` binds loopback by itself when the address it joins is loopback. The host's
`+server.local 1`, logged as "listening on UDP … on this machine alone"; the game's `-eg-local` for a hosted game's
server and its client; `+server.local 1` in every tool that starts the host (`Tools/corpus/run.py`,
`Tools/world/create.py`, `populate.py`, `stream.py`, `vantages.py`, `wade.py`, `Tools/verifiers/checks/
world_inputs_check.py` and `world_save_integrity_check.py`); the suite's own servers told local. What William
notices: no more boxes from the test runs. A game he hosts for friends will still raise one, once per build,
because that socket must be reachable.

  one joining 192.0.2.1 on 0.0.0.0, one told local on 127.0.0.1 whoever it joins; the nine addresses that do and do
  not name this machine. Each new test's reason was broken once and the tests went red: the server ignoring the
  option; a client joining loopback no longer binding to it; localhost no name of this machine; every socket bound

- The Unity-layer compile: 0 warnings, 0 errors. The host built Release.
- The box itself, twice. The first attempt was a player built while the sabotage script was sabotaging and

## Amended 2026-09-16 (M1.Bb, `M1.Bb_ONE_PLACE_FOR_THE_GAME.md`)

The default flipped: `UdpOptions.LocalOnly` is true and the host's `+server.local` defaults to 1, so a socket binds every
address only when told to. The two contrast tests above, which bound a socket on every address to read the system's
table, raised three firewall boxes in ten minutes when the suite ran from three new paths; they read the transport's
choice of address now (`UdpTransportBase.BindAddressFor`, `UdpClientTransport.BindsLocalOnlyFor`) and bind nothing.
`Build/Player-M1Ba`, the tainted build, was deleted with the other per-slice folders.
