# M1.E — The idle pause, the developer's switch, and the free look

**Status:** closed 2026-09-21; drafted 2026-09-20 on William's rulings 36, 38 and 39, to be taken after M1.4g and before the walk
(ruling 34). Three small things that live in the same two places — the controls asset that owns every key (M1.5a)
and the shell — and that he can judge in one sitting.

**Why together:** each is a few hundred lines and none of them is worth its own build, its own scenario pass and
its own round of his time. Nothing in one depends on another.

## 1. An idle game pauses itself, and says so (ruling 38)

> "if the game is ever open, and idle, i am not playing, i was looking at something or somethings … the game is
> paused, time is paused. then everything is resumed when the player refocuses the game window, or a button or
> key is pressed"

- A solo game goes idle after **60 s** with no key, no mouse button and no mouse movement, or **at once** when
  its window loses focus.
- Idle stops the world: the server in the same process takes no step, so the clock, the weather, the body's
  thirst and warmth, the animals and the autosave all stand still. A founder cannot thirst or freeze while
  nobody is there — which today he can, and does.
- Idle drops the drawn frames to **10 a second**. An idle game presently runs at over 600, which is a GPU the
  machine could be using for a build or a measured run; this is what makes an open game harmless.
- A small line says so, in the HUD's own voice: the game is paused and time with it, and what starts it again.
- **Any** key or mouse button, or the window regaining focus, resumes: the key that wakes the game does nothing
  else, so nobody wakes it by swinging a stone.
- **Never while a run is recording.** A scenario presses buttons on its own schedule and waits minutes between
  them, and the corpus's soak would pause itself and fail its own timing. The pause is off whenever the process
  was given `-eg-record`, `-eg-scenario` or `-batchmode`.

## 2. Developer mode is switched on inside the game (ruling 39)

> "make it so that dev mode is toggleable in game, not a restart with the devmode flag"

- **F2 turns developer mode on and off** (his own choice of key, 2026-09-20). With it on, F3 opens the panel
  (M1.D), the flight and noclip keys answer, and the server accepts the panel's settings. With it off, all of them
  do nothing, and F2 is the only developer key a game answers. The HUD says which way it was just turned, since a
  switch with no visible state is a switch nobody trusts.

  *What changed on the way (2026-09-20).* The switch was first drafted onto the shell's menu, so that a stranger
  would not meet it. The shell is the game's opening menu and not reachable in play, Escape already lets the mouse
  go (M1.5a), and when asked, William chose a key: F2, beside the panel's own F3.
- `-eg-dev` still starts a game with the switch already on: the scenarios and the corpus have no hands.
- The switch is the client asking; the server still decides. A solo game's own server grants it; a joined game's
  server grants it only if it was started with `+server.dev 1`, and the switch says plainly when it was refused.
- Turning the switch off puts back what dev mode changed that a normal game may not keep: the flight ends with
  the founder set down on the ground, as ending flight does today (M1.5e).

## 3. Alt frees the look (ruling 36)

> "let the alt key allow the camera to pan without moving the players body. inspired by the same mechanic in rust
> the survival game"

- Holding **Alt** turns the camera without turning the founder; the crosshair's aim follows the camera, so what
  a verb would act on is what the freed view is looking at.
- Releasing Alt returns the view to the body's facing, over a short glide rather than a snap.
- The look is bounded: the head turns no further than **135°** either side of the body's facing, and the
  existing pitch limits hold.
- It goes through the controls asset like every other key, and the controls scenario presses it (STANDARDS 5).

## Non-goals

Pausing a joined game (the world is the server's, and other players are in it); a pause menu, a settings page or
saving on pause; leaning or a body that turns its head visibly (there is no drawn body yet); a free look on the
gamepad until its layout has been judged by his hands (DEBTS); anything else on the shell's menu.

## How it is proved

- **Headless tests, written first**, on the rules that can leave the renderer: the idle clock (input keeps it
  awake, 60 s without any sends it to sleep, a recorded run never sleeps, focus lost sleeps at once); the
  developer's switch (off refuses every dev setting, on offers them, a server that refuses says so); the free
  look (the body's facing is untouched while held, the view returns on release, the turn is bounded both ways).
  Each rule broken once and seen red before it is trusted (STANDARDS 7).
- **A scenario** in the recorder that goes idle, records that the clock stood still across the sleep, wakes on a
  key and records that it ran again; and the controls scenario pressing Alt through the asset's own binding.
- **Frames** of the paused line and of the panel opened from the switch, 1440p and 1080p.
- **The corpus unharmed:** a quick corpus run whose records show no pause.
- **His hands** on all three: only he can say whether the idle message is the right size and whether the free
  look feels like the one he means (ruling 12).

## Exit record (2026-09-21)

**What exists.** `IdleWatch` in ClientCore decides when a game left alone sleeps and wakes (a minute untouched or the
focus lost; any touch or the focus back; never a recorded run but the `idle` scenario); `ClientRuntime` holds the founder,
caps the frames at ten a second, stops its clock and shows one HUD line while asleep, and the bootstrap steps the SOLO
server not at all, dropping the slept time; the waking frame's presses and the jump they queued are thrown away. "Anything
touched" is the controls asset's `Touched` action, read through `PlayerInput` like every other action, so no key or device
is named in code. `DeveloperModeMessage` (protocol 16, kind 24) carries the player's F2 to the server and the server's
answer back; `PlayerSession.DeveloperMode` is granted per player by a server that may (`MovementRules.AllowFlight`: every
SOLO game, a host with `+server.dev 1`), and `GameServer.MovementRulesFor` gives flight only to a switched-on session;
F3's panel, the settings and the flight follow what was granted, and turning it off sets a flying founder down while
turning it on again starts the developer's session over with the noclip on. `FreeLook` in ClientCore holds the view's
offset while Alt is held (135° at most) and glides it home in a quarter of a second; the mover walks and the server is
sent the body's facing, the camera and the crosshair take the view's. The `idle` scenario (`Recorder.Idle.cs`, run by
`Tools/world/idle.py`) and the controls scenario's F2 and Alt steps prove them on the built player. Every run tool now
runs the player on a copy of its world through `wade.copied`. What a player notices: a game left alone says it is paused
and its clock stands; F2 turns developer mode on and off with a notice; Alt looks round without turning the body.
