**Status:** opened 2026-09-24 on William's yes to two of the four uses of his new machine put to him that day: the side

## Why

- The two sessions shared one working tree, one git index, one Unity project, one Build/Harness and one Engine/.build
  (WORKING.md, "Two agents, one machine"): one Unity at a time, a suite in one session locking the other's DLLs, commits of
  shared docs by pathspec, and holds for every timed run. On 2026-09-23 the side worker held the machine quiet for hours
  while the main session timed M1.6g and walked the corpus, and the main session waited on its builds before.
- Nothing ran the whole set of checks unless a slice asked for one. A scenario or a verifier that turned red between slices
  was found by the next slice that happened to run it: the corpus's corrections on a slide's landing were met by BF.4's
  corpus on 2026-09-23, a day after M1.5i changed the slide, because no full corpus had walked since.
- The machine is William's, and shared: his game, his television on the main screen, and since ruling 47 his sleep.

## What this slice promises

1. **A copy knows what it is.** An untracked `.eg-copy.json` at a copy's root names the copy (`main`, `side` or `sweep`), the
   offset its tools add to every port, and the main copy's root. `Tools/world/machine.py` is its one reader. Without the
   file a copy is the main one with no offset, so the main copy and everything run in it are as they were.
2. **The copies do not collide.** Every port a tool opens is taken through `machine.port()`. `install.py` and
   `editmode.py` refuse only while Unity holds their own copy's project (its lockfile), not while any Unity runs, and
   `install.py` refuses `--into player` outside the main copy: Build/Player is William's and lives in the main copy alone.
3. **The copies share what is one fact.** Artefacts, Data/global, Data/regions, Data/cache and Tools/.venv are directory
   junctions to the main copy's, so a frame, a world or a report named in the docs is found from any copy, and 150 GB is not
   held three times. The Unity Library is copied, never shared (two editors on one Library corrupt it).
4. **The side copy.** `C:\Users\willi\projects\EarthGame2-side`: a clone with origin on GitHub and the hooks on, a port offset
   of 1000. The side worker commits there, pulls with rebase and pushes; the main session does the same from the main copy.
5. **The sweep.** `Tools/sweep/sweep.py`, run in the sweep's copy (`EarthGame2-sweep`, offset 2000), which no one edits:
   brings the copy to origin/main and runs every check on it. The engine suite, the Unity-shaped compile, the edit-mode
   tests, the build into its own Build/Harness and the dedicated host; fresh worlds of Bherwerre, the 8 km valley and the
   whole valley; the verifiers on those worlds and those that need none; every scenario in the built game, with the check of
   its records where one exists; the corpus with the soak and its three checks; and the vantages' frames of the three
   worlds. A failed step does not stop the rest; a step whose build or world failed is skipped and says why. Each sweep leaves
   `Artefacts/sweeps/<stamp>/` (`report.md`, `report.json`, a log a step, the runs) and `Artefacts/sweeps/latest.json`, and
   the report puts first the steps that were green in the sweep before and are red in this one.
6. **The sweep gives way.** Before each step it waits while: it is the quiet hours (ruling 47; 22:00 to 08:00); William's
   game runs from the main copy's Build/Player; a session has asked for quiet (`machine.quiet()`, which a timed run of
   `vantages.py --hold` takes); or the machine's free memory is short of what the step needs. It never ends a step part-way:
   a request waits for the step in hand to finish, so the corpus is run a scenario to a step and no step is longer than the
   soak's half hour, and the report counts every wait and what it was for. One sweep at a time; the sweep never starts in
   the quiet hours, and it brings its copy up to date with a fast-forward pull, which refuses rather than overwrites.
7. **The quiet hours hold for every tool.** The tools that work the machine hard (the scenario runner, `vantages.py`, the
   corpus, `install.py`, `editmode.py`, world creation and population, the streaming check) refuse to start in the quiet
   hours unless `EG_QUIET_HOURS_OK=1` is set, which a session sets only when William asks for a run then.

## Non-goals

- No timing in the sweep: its numbers would be taken while the sessions work. Frame costs stay the sessions', each run
  under a quiet request.
- No scheduled task: a session starts a sweep in the daytime, after it pushes. The processor split for timing (one half of
  the 9950X3D for a timed run, the other for everything else) and the permission list are measured and put to William on
  their own.

## How it is proved

- The copies: the same scenario run at once in the main and side copies, both green; `install.py` in the side copy building
  its own harness while a Unity batch runs on the main project; `--into player` refused there.
- The quiet hours: each guarded tool refusing with `EG_QUIET_HOURS_OK` unset when the clock is inside them, by a clock handed
  in (`machine.in_quiet_hours(now)`), never by waiting for the night.
- The sweep: run once end to end at origin/main, its report read; a quiet request made during a step, the sweep finishing
  that step and waiting before the next until the request is gone, the report counting the wait; a second sweep refused
  while one runs.
- The side worker working in its copy: a commit pushed from it.
