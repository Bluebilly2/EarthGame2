## What this slice promises

1. **Definitions.** `Definition` and `DefinitionCatalogue` in the engine: a stable string key per definition
   (`plant/<name>`, `stone/<name>`, `animal/<name>`, `item/<name>`, `player`), hashed FNV-1a 32 into a
   `DefinitionId` at load; the catalogue is built from the tables that exist (`PlantSpecies.All`, `StoneType.All`,
   `AnimalSpecies.All`) plus the items this slice introduces (`item/cobble`, `item/stick`) and `player`. Each
   definition states its kind, whether it is spawnable as an entity in M1 (items now; trees and animals when M1.6
   and M1.7 land), and for an item its mass and bounding radius: physics values live once, in the engine. A test
   fails on any two keys sharing a hash, on a key not in the stated form, and on a spawnable definition without a
   mass.
2. **The entity store.** `EntityStore`, owned by `WorldState.Entities`: `EntityId` (a 64-bit count, allocated in
   order, never reused; the next id is state), `Entity` (id, definition, position in local metres, yaw, the tick it
   was spawned, and plain-struct components with a dirty mask); lifecycle Spawn → Init (the tick after the
   spawn, when systems first see it) → Kill (removed at the end of the tick; the id retired); iteration in id
   order; `Within(east, north, radiusM)`; a `Changed` mask per entity since it was last cleared, for replication.
   The one component this slice carries is `Item` (whether it rests); the store's shape is the promise, not the
   component list.
3. **The tiered tick.** `WorldState.Step` runs the fast systems in a stated order; the first is `ItemFall`: an item
   spawned above the ground falls at 9.81 m/s² per fast tick until it meets the heightfield (the sea's floor
   under the sea), and rests there — where the server says, plan §4.4. `WorldState.SlowLayers` holds
   `ISlowLayer.AdvanceTo(worldHours)` layers scheduled by `SlowScheduler` per 512 m cell: a cell within the
   interest radius of any player advances every tick, a cell farther away every 60 ticks, and a cell that has not
   been advanced catches up in one `AdvanceTo` when it is next scheduled (the layer is responsible for being
   analytic over the gap). A test layer proves the two cadences and the catch-up.
4. **Save and digest.** `regions/r.X.Y.egr` (format `eg2.region` version 1): one little-endian binary file per
   512 m cell, holding the entities whose position lies in it — magic `EG2R`, version, the cell's indices and size,
   the entity count, a CRC-32 of the records, then per entity: id, definition key, position (three doubles), yaw,
   spawn tick, and its components with their fields. Written to `.part` and moved; a cell's file is removed when
   it holds nothing. `players/<name>.egp` (format `eg2.player` version 2, binary: magic `EG2P`, the fields of
   version 1's JSON plus wading and stance, which version 1 dropped and the round trip needs) replaces the JSON as
   a versioned change: the loader reads both, the writer writes version 2. `world.json` gains `next_entity_id`
   (additive). `digest.txt` is written beside `world.json` at every save. The world digest gains every entity
   (id, key, position and yaw at the stated resolutions, the components' fields) and the next id. Tests: a round
   trip (save → load → the same digest, the id counter carried); the save law by sabotage (each persisted field
   flipped in turn changes the digest); two saves of one state are byte-identical; a solo world's folder is
   byte-identical to a server's.
5. **Entities on the wire (protocol v4).** `EntitySpawn` (id, definition id, tick, position, yaw, every component
   in full; reliable), `EntityState` (id, tick, the changed fields by mask; unreliable), `EntityGone` (id, and
   whether it died or left the viewer's interest; reliable). Each session keeps an interest set: the Welcome's
   snapshot carries every entity within `ServerConfig.InterestRadiusM` of the spawn before `SnapshotEnd`; after
   each tick a session is sent spawns for entities that entered its set, states for entities in it that changed,
   and gones for those that died or left it — leaving needs 50 m more than entering, so an entity on the edge does
   not flap. `ServerConfig.EntityBytesPerTick` (4096) caps what one session is sent per tick: spawns and states
   beyond it wait, their dirty flags holding them; a gone never waits. `ProtocolInfo.Version` becomes 4 and a
   version-3 Hello is refused with both numbers.
6. **The client mirror.** `EntityMirror` in ClientCore: the entities the server has shown this client, each with
   its latest state and the tick it was stated at; spawn and gone events; `GameClient.Entities`. Its digest
   (ids, keys, positions and yaw at the stated resolutions) is computed the same way as the server's digest of a
   session's interest set, so a harness compares strings as N3 and N4 do for bodies.
7. **Definitions bound to prefabs (Unity).** `PrefabRegistry`, a ScriptableObject asset under `Resources/EarthGame`,
   maps definition key → prefab; an edit-mode test asserts every spawnable definition has exactly one binding
   and every binding names a definition; placeholder prefabs for `item/cobble` and `item/stick`. `ClientRuntime`
   instantiates the prefab on spawn, moves it on state, and destroys it on gone. Frames at 1440p and 1080p of a
   cobble and a stick resting near the wake, recorded windowless, are the proof (STANDARDS 15); whether they rest
   where his eyes expect is the owner's.
8. **A headless two-client session** over the in-memory transport, as a dotnet test: two clients join a server
   that has spawned items near the wake; both mirrors hold the same ids and their digests equal the server's for
   their interest sets; a client that reports itself beyond the radius is sent gones and, back inside, spawns;
   a killed item leaves both mirrors.
9. **The host's commands and the populate harness.** `EarthGame.ServerHost` gains the console commands
   `spawn <key> <east> <north> [<up>]` (an item dropped there, falling if above the ground) and `save`;
   `Tools/world/populate.py` runs the host on a world folder, spawns a stated set of items around the wake, saves,
   and prints the digest the server wrote, so the verifier has a folder to read.
10. **Verifier `save_check.py`** (CANON ruling 17; independent of the tool by implementation): reads `world.json`,
    `digest.txt`, `players/*.egp` and `regions/*.egr` with Python alone by the formats §10 states, checks every
    region file's CRC and that every entity's position lies in the cell its file names, recomputes the world
    digest from the stated lines and prints it beside the server's; exit 0 only when the two match. Gate `M1.3`:
    the suite, the Unity-layer compile, `populate.py` on a fresh world, `save_check.py` on its folder.

## Non-goals

Trees and animals as entities (M1.6, M1.7); picking up, dropping and the verb rule (M1.5: items are spawned only
by the host's command here); the player's body as an entity (M1.5, with the verbs); layer diffs in `.egr` (the
format reserves a count of them, zero for now); a bandwidth budget shared across sessions (the cap is per
session); a grid for interest (a radius filter serves 8 players, ARCHITECTURE §7 rule 5); rendering beyond a
placeholder mesh (M1.4, M1.6).
