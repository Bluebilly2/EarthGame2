# Contract M1.Bb — One place for the game

**Status:** opened and closed 2026-09-16, on William's "use a better versioning system, i dont want each new version of
the game to be in a new folder that asks for perms here in the claude harness and in my firewall, my firewall has been
popping up a few times in the last ten mins." Owner: Claude (Fable 5.1). A follow-up to M1.Ba (a socket for this
machine alone), whose contrast tests turned out to be the boxes of the last ten minutes.

## What was found

- **Every new folder an exe runs from is a prompt.** The harness asks the owner before running a new program path,
  and Windows' firewall asks once per program path for a socket bound to every address. Since M1.Ba the agent had
  built every slice into its own `Build/Player-<slice>`: forty-one folders by this morning, each a prompt or two.
- **The last ten minutes' boxes were the test suite's.** M1.Ba's two contrast tests bound a socket on every address on
  purpose, to read the system's table and prove the default did; the suite had just been run from two temporary
  checkouts and a scratch harness, three new paths, three boxes. A SOLO game opens no socket at all.
- **The build already had one home.** `CIBuild.BuildWindows` writes to `Build/Player` unless told otherwise; the
  per-slice folders were the agent's habit and WORKING.md's rule, written for the day the owner's running game must
  not be overwritten.

## What this slice promises

1. **Two folders, replaced in place.** `Build/Player` is the owner's game and `Build/Harness` the automated runs';
   `Tools/build/install.py` is the one way a build lands: Unity builds into `Build/.staging` (nothing runs from
   there), the tool writes `version.json` beside the exe (commit, branch, dirty or not, the time, a label), refuses to
   touch a folder any process runs from (the owner's game is never killed and never overwritten under him), keeps the
   folder it replaces as `<folder>.previous` for one step back, and moves the build into place. `--show` says what is
   installed where. The runs' tools default to `Build/Harness`, and their `--build` goes through the tool.
2. **A build is told apart by its version, not its folder.** The player logs it on its first line (`BuildInfo`: the
   label, the commit, `+dirty`, the time, the branch) and the run log's header carries `build_label`, `build_commit`,
   `build_dirty` and `build_utc` (additive, `eg2.run`); the editor and a hand-copied player say "unversioned".
3. **Closed unless opened.** `UdpOptions.LocalOnly` defaults to true, and the host's `+server.local` to 1: a socket
   binds every address only when told to, for a game hosted for friends (`-eg-mode host` without `-eg-local`, the
   game's own choice) or a dedicated server told `+server.local 0`. The suite binds no socket on every address: the
   two contrast tests read the address the transport would bind (`UdpTransportBase.BindAddressFor`, the client's
   `BindsLocalOnlyFor`), one owner with the bind itself, and open nothing.
4. **The old folders go, and the shortcut follows.** The forty-one `Build/Player-*` folders are deleted; the owner's
   desktop shortcut points at `Build/Player/EarthGame2.exe`.

## Non-goals

A launcher, an updater, a version shown on the shell's screen (the log and the run log carry it; the shell can show it
when the shell is a slice again). Renaming the builds' processes (Windows names its rule by the exe's path).

## How it is proved

`dotnet test` over the whole tree, the two rewritten contrast tests red once (the address helper broken) and green
after; the Unity-shaped compile; the tool run for real: `--into both` from a clean main, the version logged by the
player on its first line, `--show` naming both; a night run from `Build/Harness`; the owner's own play from
`Build/Player` and no firewall box while he plays.
